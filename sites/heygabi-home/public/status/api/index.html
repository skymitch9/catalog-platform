Shelf parity reporter

writes one number, one route

Used by 03-shelf-parity.sh on the shelf server to post how many books match Drive. It cannot read the library, cannot pass the Google gate, and is accepted on no other route — the worst a leaked one can do is report a false number.

How to install it on the shelf server
  1. Click Generate key above. The value appears once — copy it before leaving the page.
  2. On the server, save it (the button copies this whole line for you): 
    echo 'SHELF_PARITY_TOKEN=<the value>' | sudo tee /srv/shelf/.parity.env
sudo chmod 600 /srv/shelf/.parity.env
  3. Check it landed without printing it: 
    sudo test -s /srv/shelf/.parity.env && echo 'token file present'
  4. Run the reporter once: ./03-shelf-parity.sh
  5. Come back here — Last used should show a moment ago, and the parity bar on Health stops saying “never reported”.

Rotating a key

Generating again replaces the key. By default the old one keeps working for 24 hours, so if the paste goes wrong the next scheduled run still reports and nothing goes dark while you fix it.

Rotating because you think it leaked? Tick Kill the old key immediately. A grace window is the wrong behaviour when the whole point is that the old value must stop working now.

Nobody can look a key up after the fact — only a hash is stored. Lost it? Generate a new one; that is the supported path, not a recovery.

Keys are generated in the auth Worker and stored as a SHA-256 hash. The value itself is transmitted once, to this page, at the moment you create it — there is no route that returns it again, so a key that is lost is replaced rather than recovered.
