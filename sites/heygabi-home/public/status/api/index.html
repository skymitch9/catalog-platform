Installing a key on the machine that uses it
  1. Click Generate on the key you want. The value appears once — copy it before leaving the page.
  2. On that machine, save it into the file or secret named in Lives at. For the shelf server that is: 
    echo 'SHELF_PARITY_TOKEN=<the value>' | sudo tee /srv/shelf/.parity.env
sudo chmod 600 /srv/shelf/.parity.env
  3. Check it landed without printing it: 
    sudo test -s /srv/shelf/.parity.env && echo 'token file present'
  4. Make the machine do its thing once, then come back here — Last used should show a moment ago.

Rotating, and what the grace window is for

Generating again replaces the key. By default the old one keeps working for 24 hours, so if the paste goes wrong the machine keeps working while you fix it.

Rotating because you think it leaked? Tick kill the old key immediately. A grace window is the wrong behaviour when the whole point is that the old value must stop working now.

⚠️ If a machine authenticates on the previous key, this page says so. That is the signal a rotation was started and never finished — the new key was generated but never installed.

Nobody can look a key up after the fact; only a hash is stored. Lost it? Generate a new one — that is the supported path, not a recovery.

Info

Where every token in the estate comes from, and how each one is rotated — including the ones with no button here. ⚠️ “No button” does not mean “do not rotate”: two of these are Google-issued and rotate with a native two-key overlap, no outage window.

Keys are generated in the auth Worker and stored as a SHA-256 hash. The value itself is transmitted once, to this page, at the moment you create it — there is no route that returns it again, so a key that is lost is replaced rather than recovered.
