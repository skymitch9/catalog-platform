Installing a key on the machine that uses it
  1. Generate the key on its card above. The value appears once — copy it before leaving the page.
  2. On that machine, save it into the file or secret named in that key’s Lives at. For the shelf server: 
    echo 'SHELF_PARITY_TOKEN=<the value>' | sudo tee /srv/shelf/.parity.env
sudo chmod 600 /srv/shelf/.parity.env
  3. Check it landed without printing it: 
    sudo test -s /srv/shelf/.parity.env && echo 'token file present'
  4. Make the machine do its thing once, then reload — Last used should show a moment ago.

Rotating, and what the grace window is for

Generating again replaces the key. The old one keeps working for 24 hours, so if the paste goes wrong the machine keeps working while you fix it.

Rotating because you think it leaked? Tick kill the old key immediately. A grace window is the wrong behaviour when the point is that the old value must stop working now.

⚠️ Every generate and rotate asks you to confirm first, and the dialog names the key. These buttons look alike on purpose — the confirmation is what stops a mis-click becoming a rotation.

Nobody can look a key up afterwards; only a hash is stored. Lost it? Generate a new one — that is the supported path, not a recovery.

Keys are generated in the auth Worker and stored as a SHA-256 hash. The value itself is transmitted once, to this page, at the moment you create it — there is no route that returns it again, so a key that is lost is replaced rather than recovered.
