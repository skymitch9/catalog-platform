The 12 AI commandments

The estate's global rules — how everything here gets built (tap to expand)
  1. Three doc folders: access/ (how to operate — secrets named, never valued), info/ (how it works, dates on every measured fact), and one living work log. Never duplicate a fact across them.
  2. Agent instructions stay thin — only what bites in the first ten minutes, pointing at the work log for everything else.
  3. Stale docs are bugs — if reality disagrees with a doc you touched, fix the doc in the same session.
  4. Every report states what was NOT verified. No guessing to unblock — an unavailable fact is reported unavailable.
  5. Shipped ≠ verified. Track them separately. Run the change; don't reason about it.
  6. Guards are scripts, not advice — deploys refuse a dirty tree; escape hatches are deliberate env vars; write the guard the day of the incident and name it after it.
  7. Every ask goes on the todo list the moment it's said — never memory-only.
  8. Big model plans and reviews; cheap models build from tight briefs — exact paths, rules, verification steps, off-limits files.
  9. Concurrent agents claim work in an append-only log before starting, never rewrite entries, and write down what they couldn't solve.
  10. If agents are metered: read the budget before every dispatch and after every landing — an agent's cost is invisible until it finishes — and a limit is a pause with a scheduled resume, never a stop.
  11. Anything visible ships with its review link — the exact deep URL plus one line on what to look at. A change you have to hunt for isn't delivered.
  12. Directory deploys ship whatever's on disk — deploy only from a committed-clean tree (or a throwaway worktree of HEAD), or you'll ship a colleague's half-built work.
