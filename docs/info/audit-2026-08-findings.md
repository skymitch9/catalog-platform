## 1. How to read this

**79 findings survived verification** across 13 review units. Each was produced
by an Opus reviewer reading the unit in full, then handed to a separate Opus
**refuter** whose job was to kill it — checking it against the source, against
`KNOWN_ISSUES.md`, and against the test suite. **7 further findings were
refuted and are not listed here.** The refuter could also re-rate: where it
did, the row shows `orig → final` and the final rating is the one used for
ranking.

Severity, as used here:

| | Meaning |
|---|---|
| **Critical** | Credential exposure or irreversible data loss is one ordinary action away. |
| **High** | A real person or an automated caller gets a wrong answer, a lost write, or a broken feature, today, with no workaround. |
| **Medium** | Reachable and wrong, but bounded — a mislabelled refusal, a stale doc that will mislead the next session, a guard that cannot fire. |
| **Low** | True, worth fixing, but the harm is cosmetic, latent, or needs a condition nobody has created. |

**Counts:** 1 critical · 7 high · 29 medium · 42 low.

## 7. What this audit did NOT cover

⚠️ **Read this before treating the absence of a finding as evidence of health.**

**Other repos.** This document covers `catalog-platform` only. The audit's
other three targets — `bookbuddy/library_catalog`, `bookbuddy/audiobook_catalog`
and `boardbuddy/Board_Game_Catalog` — get their own `audit-2026-08-findings.md`
in their own `docs/info/`. Several findings here **point at** those repos
(F13's shared-memory target, L22's app-worker wire shape, F36's role floor) and
were not chased across the boundary.

**Anything that needs to run.** No production request was made, no database or
KV read, no `wrangler secret list`, no browser opened, no Firestore document
inspected. Concretely unmeasured, and named in the rows that depend on them:

- whether a minted `estate:conductor:token` exists in KV and whether
  `ESTATE_CONDUCTOR_TOKEN` is still set (L1);
- whether `ESTATE_APP_TOKEN_LIBRARY2` is currently set in production (L3) —
  `env.ts:122` and `friend-ingest-design.md:217` disagree;
- how many live ebook rows carry a non-null `universe` (F9) — this decides how
  much leaks today, not whether the gate is missing;
- whether any live row has a whitespace-padded `series` (L6);
- whether `site_roles/{uid}` holds an owner doc for the second owner account,
  which would mask the everyday half of F36;
- whether `GABI_SHELF` is genuinely `on` in the deployed lane (F21);
- the actual reaction of the `audio_streams` evictor (F3) — its consumer lives
  in another repo.

**Out of scope by construction** (per the plan): `node_modules`, `dist/`,
generated packages, vendored pdf.js, and the ~9 dead `worktree-agent-*`
branches.

**Not a security assessment.** No threat modelling, no dependency/CVE scan, no
attempt to chain findings, no test of authentication beyond reading the gates.
The `exposure` and `secrets` categories here mean "a reviewer read the code and
this is what it does", not "an attacker was simulated".

**Not a performance or cost review.** L12's benchmark is desktop V8, an
order-of-magnitude guide only; nothing else was timed.

**Sibling repos' Firestore rules, the shelf server, and the home machine's
scheduled tasks** were read only where this repo's code names them.
